# 策略现状盘点 + 优化方向报告模板

> 来源：2026-06-07 用户 说"你研究一下如何继续优化投资策略模型"时的实证输出

## 触发场景

用户 发出以下任一信号时使用本模板：
- "研究一下如何优化 / 改进 / 提升"
- "评估一下当前策略 / 现状 / 模型"
- "下一步应该做什么 / 还有哪些可以做的"
- "这模型有什么问题 / 还能怎么调"

## 反模式（不要做）

- ❌ 直接给 5-10 条"建议"而不看现状
- ❌ 列完整 A/B/C/D 选项表让 用户 选（他反感"?" = 负面反馈）
- ❌ 长篇背景铺垫再给结论
- ❌ 给 80% 准确率承诺（做不到，画饼）
- ❌ 用 lorem ipsum 数据举例，必须从 sqlite / CSV / cron list 抓真实数据

## 模板（4 步）

### Step 1: 现状盘点（一屏表，5-8 行）

按"层"切分，每行：层 / 状态 / 具体缺口。

| 层 | 状态 | 问题 |
|---|---|---|
| **数据** | ✅ 健康 | 13+ 源，900+ intel，5 个 10 年 CSV |
| **规则** | ⚠️ 部分 | 19 条入库，但 4 条 REDUCE 仍 enabled=1（与实证矛盾） |
| **回测** | ❌ 盲点 | 5 年 QQQ 跑过，**跨周期 2000-2010 熊市从未跑** |
| **信号** | ❌ 空转 | signals 表 0 条，verify_signals 永远无数据可填 |
| **决策** | ❌ 缺失 | decisions 0 条 |
| **持仓** | ❌ 缺失 | holdings 表空，4 只基金没建档 |
| **Cron** | ⚠️ 部分 | 4 个 cron 跑着，几个 delivery error 待 self-heal |

**关键技巧**：
- ✅ ⚠️ ❌ 三档即可，不要 5 档（用户 偏好简明）
- 数字要真实——sqlite query / cron list / 文件大小都是一手数据
- ❌ 比 ⚠️ 多 = 系统有真实问题要承认，不要"全 OK 看起来不错"

### Step 2: 5 个优化方向（按 ROI 排序）

每个方向 1 行：方向 / 成本 / 收益 / 谁负责

#### 排序原则
- **🔴 P0**（最高）：1-2 小时做完 + 立刻影响本金安全 / 解决已知失败模式
- **🟡 P1**（中）：1-2 天让系统从"定义"变成"运行"
- **🟢 P2**（低）：1-2 周探索性 / 长期价值

#### 典型 P0 例子
1. **关闭失败 REDUCE 规则**——5 行 SQL，5 分钟，立刻减误触发风险
2. **跨周期验证金子规则**——4 条规则 × 熊市 10 年，1-2 小时，堵最大盲点

#### 典型 P1 例子
3. **把金子规则扩到 GLD/SPY**——同一规则在 3 标的跑，黄金/标普也有金子
4. **让 signals 真正产出**——跑 1 次 evaluate_today.py，cron 才有数据可回填

#### 典型 P2 例子
5. **新规则研究**（RSI<30 / 5/20/60 多头排列等）——backtest 验证后再决定

### Step 3: 指出最高优先级 1-2 项

明确写：
> "**我的建议：先做 P0 两条（合计 1-2 小时）**
> 1. 关 REDUCE（5 分钟）→ 立刻生效
> 2. 跑跨周期回测（Yahoo 2000-2010 数据 + 4 条规则 × 3 标的）→ 看熊市是否还成立"

这让 用户 看到"如果干，需要多久"+"具体做什么"，决策成本极低。

### Step 4: 直接开干 vs 等确认

**研究任务**（如"研究一下")：**给方案 + 等一句"OK 开干"或调整方向**。
**开干任务**（如"把 REDUCE 规则关掉"）：**直接做，不问**。

收尾句模板：
- "**直接开干**还是你要调整方向？"（研究用）
- "开干。完成后发你截图。"（执行用）

## 关键反例（绝对不要做）

### ❌ 反例 1：列菜单
> "你想先做 A 还是 B？A 是跨周期验证，B 是关闭 REDUCE..."
> → 用户 回 "?" = 不耐烦

### ❌ 反例 2：承诺做不到的
> "通过这套模型我们可以实现 90% 准确率"
> → 实际：跨标的回测 33-51%，生存者偏差下技术面 80% 也是牛市的

### ❌ 反例 3：只讲流程不讲数据
> "我们应该先用 grid search 跑参数..."
> → 用户："数据源以及数据质量是第一步"——流程前先看数据现状

### ❌ 反例 4：自吹自擂
> "我们已经有 19 条规则和 4 个 cron..."
> → 用户 关心的是"还能怎么优化"，不是"已经做了什么"

## 关键引用（来自 memory + 用户 原话）

- "数据源以及数据质量是第一步"（用户 2026-06-06）→ 现状盘点要从数据查起
- "互相影响的参数需要不断迭代调整优化验证"（用户）→ 优化方向要含"参数扫描/迭代"
- "你总是在围绕我的持仓，市场上其他热点和投资机会都没有吗?"（用户 2026-06-06）→ 优化方向必须含"持仓之外扫描"
- "持续执行原则"——研究后直接给"先做 X"方案，不要反复问
- "先做不要问 A/B/C/D"（2026-06-06 用户 反馈）——指出最高优先级即可，不列选项表
- "做不到就说做不到"——P0 里如果某项做不到就明确写"无法做到：X"并解释

## 模板使用后效果

- 用户 一眼看到 7 行现状 → 知道系统在哪个层级卡
- 5 个方向按 ROI 排序 → 知道哪些事最值得做
- 最高优先级 + 时间估算 → 决策成本 < 5 秒
- 反问"开干 vs 调整" → 给他控制权但不是负担
